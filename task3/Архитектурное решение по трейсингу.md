### Анализ и места возможных потерь заказов

Заказ проходит через несколько сервисов: онлайн-магазин → Shop API → (S3) → RabbitMQ → CRM API → CRM → (RabbitMQ) → MES API → MES → MES DB → обратно через RabbitMQ в CRM. На каждом этапе возможны сбои:
- Потеря сообщения при отправке в RabbitMQ.
- Ошибка при расчёте цены в MES (долгий расчёт, падение).
- Необработанное сообщение о смене статуса.
- Ошибка при записи в БД.
- Сбой в самом MES при взятии заказа оператором.

**Системы для покрытия трейсингом**:
- Shop API (Java)
- CRM API (Java)
- MES API (C#)
- RabbitMQ (как транспорт)
- Фоновые процессы (расчёт цены)
- Клиентские части (фронтенд) – опционально, для полной картины можно использовать OpenTelemetry для браузера.

### Данные для трейсинга

Каждый спан (единица работы) должен содержать:
- Trace ID – уникальный идентификатор заказа (или процесса).
- Span ID – идентификатор операции.
- Имя операции (например, "calculate price", "save order", "send to queue").
- Время начала и длительность.
- Теги:
  - `order_id` – номер заказа.
  - `user_id` – идентификатор клиента/партнёра.
  - `status` – статус заказа (до/после).
  - `error` – признак ошибки и сообщение.
  - `queue_name` – для операций с очередью.
  - `http.method`, `http.url`, `http.status_code` – для HTTP-запросов.

### Мотивация

Трейсинг позволит:
- **Проследить полный путь заказа** – увидеть, где именно заказ зависает или теряется.
- **Измерить время** каждого этапа – выявить узкие места (например, долгий расчёт).
- **Обнаружить потерянные сообщения** – если спан отправки в очередь есть, а спан получения нет, значит сообщение не дошло.
- **Ускорить отладку** – вместо гаданий по логам разработчик видит трассу и сразу понимает, какой сервис не сработал.
- **Улучшить SLA** – на основе данных можно оптимизировать медленные этапы.

Технические метрики:
- Процент успешных завершений заказов.
- Среднее время прохождения заказа от создания до отправки.
- Количество ошибок на каждом этапе.

Бизнес-метрики:
- Доля заказов, выполненных в срок (3 недели).
- Удовлетворённость клиентов (косвенно).
- Снижение числа обращений в поддержку.

### Предлагаемое решение

Используем **OpenTelemetry** как стандарт для сбора трасс. Компоненты:
- **Agent/Library** – встраивается в каждое приложение:
  - Для Java – OpenTelemetry Java agent или SDK.
  - Для C# – OpenTelemetry .NET.
  - Для RabbitMQ – инструментирование через библиотеки (например, OpenTelemetry.Instrumentation.RabbitMQ).
- **Collector** – OpenTelemetry Collector для приёма, обработки и экспорта трасс.
- **Backend** – Jaeger (или Tempo) для хранения и визуализации трасс.

### Компромиссы

- **Стоимость внедрения** – требует времени разработчиков на инструментирование, настройку инфраструктуры.
- **Производительность** – небольшой оверхед от сбора трассировки, но обычно приемлем.
- **Конфиденциальность** – в трассировку не должны попадать персональные данные клиентов (можно настроить фильтрацию).
- **Сложность отладки асинхронных сценариев** – если сообщение теряется до попадания в очередь, трассировка может оборваться.

### Безопасность

- Аутентификация в Jaeger UI – через SSO компании (например, Keycloak), доступ только у сотрудников с ролью "Разработчик" или "Поддержка".
- Передача трассировки по зашифрованным каналам (TLS).
- В трассировке не передаются чувствительные данные (пароли, токены) – настройка фильтрации атрибутов в Collector.
- Журналы доступа к Jaerger для аудита.

### Дополнительное задание: мониторинг на основе трейсинга

Создаём автоматический мониторинг процесса прохождения заказа:
- **Алерты** на основе анализа трасс:
  - Если заказ находится в статусе "PRICE_CALCULATED" более 2 часов – отправлять письмо оператору (вероятно, оператор не взял).
  - Если этап "MANUFACTURING_STARTED" длится более 3 недель –  отправлять письмо оператору.
  - Если количество ошибок на этапе расчёта превышает порог.
- **Инструментарий**: OpenTelemetry Collector может экспортировать метрики (например, длительность спанов) в Prometheus, а оттуда алерты.
